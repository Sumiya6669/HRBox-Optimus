# Что нужно применить вручную

Две вещи. Обе — один раз.

## 1. SQL: права доступа

Supabase → **SQL Editor** → вставить целиком содержимое
`supabase/migrations/0014_role_permissions.sql` → **Run**.

Что создаётся:

- таблица `role_permissions` — какая роль какие разделы видит;
- функции `my_permissions()` и `set_role_permissions()`;
- защита от самоблокировки: администратору нельзя закрыть «Пользователей»,
  «Права доступа» и «Настройки» — иначе права было бы уже не вернуть;
- значения по умолчанию, повторяющие текущее поведение портала. То есть сразу
  после применения ничего не изменится: сотрудник видит кабинет, HR —
  администрирование, администратор — всё.

Если ещё не применяли `0013_wallet_analytics.sql` (аналитика по баллам) —
примените сначала его, потом этот.

## 2. Edge-функция: создание пользователя с паролем

Нужна для варианта «Добавить пользователя → Сразу с паролем». Ссылки и письма
работают и без неё.

**Вариант А — через дашборд.** Supabase → **Edge Functions** → **Deploy a new
function** → имя `create-user` → вставить содержимое
`supabase/functions/create-user/index.ts` → Deploy.

**Вариант Б — через CLI:**

```bash
supabase functions deploy create-user --project-ref dadnsuviohnzisksdbuj
```

Отдельных секретов задавать не нужно: `SUPABASE_URL`,
`SUPABASE_SERVICE_ROLE_KEY` и `SUPABASE_ANON_KEY` Supabase подставляет сам.

Проверить: «Пользователи» → «Добавить пользователя» → вкладка «Сразу с паролем».
Если функция не развёрнута, портал скажет об этом прямым текстом, а не
«неизвестная ошибка».
