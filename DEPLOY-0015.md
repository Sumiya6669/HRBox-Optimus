# Курсы и тестирование — что применить

## 1. SQL

Supabase → **SQL Editor** → вставить содержимое
`supabase/migrations/0015_courses_lessons_tests.sql` → **Run**.

Порядок, если предыдущие ещё не применяли: `0013` → `0014` → `0015`.

Что создаётся:

- `course_lessons` — уроки курса (видео, документ, текст, ссылка);
- `lesson_progress` — прохождение уроков; прогресс курса пересчитывает триггер;
- `course_tests`, `test_questions`, `test_options`, `test_attempts` — тесты;
- функции `complete_lesson`, `start_test_attempt`, `submit_test_attempt`,
  `course_stats`;
- бакет `course-media` для видео (500 МБ, MP4/WebM/MOV/PDF).

### Важно про размер файла: 500 МБ зависят от тарифа Supabase

Код и бакет рассчитаны на 500 МБ, но последнее слово за тарифом проекта:

| Тариф Supabase | Максимальный размер одного файла |
|---|---|
| Free | **50 МБ** — жёсткий потолок, обойти нельзя |
| Pro и выше | до 500 ГБ |

На бесплатном тарифе ролик больше 50 МБ отклонит сам сервис, ещё до бакета, —
никакой настройкой это не меняется. Если видео крупнее, нужен план Pro.

После перехода на Pro поднимите лимит вручную: Supabase → **Settings → Storage
→ Upload file size limit** → 500 MB. По умолчанию он остаётся низким даже на
платном тарифе.

Проверить текущее значение: Supabase → Storage → Settings. Там же убедитесь,
что бакет `course-media` появился после миграции.

## 2. Как наполнить курс

**Администрирование → Курсы → «Уроки и тест»** у нужного курса.

Вкладка **Уроки**:

1. «Добавить урок» → название → тип «Видео».
2. Перетащите файл в область загрузки или нажмите «Выбрать файл».
3. Галочка «Обязательный урок» — влияет на процент прохождения. Снимите её для
   дополнительных материалов.
4. Порядок уроков меняется стрелками.

Вкладка **Итоговый тест**:

1. «Создать тест» — сразу с настройками по умолчанию (порог 80 %, 15 минут,
   3 попытки), их можно поменять тут же.
2. «Добавить вопрос» → текст → варианты → галочками отметить верные.
3. «Показывать верные ответы после сдачи» по умолчанию выключено — иначе первый
   сдавший разошлёт ключ остальным.

## 3. Как это видит сотрудник

**Кабинет → Обучение → курс**: слева программа курса, справа материал. Кнопка
«Начать» открывает видео (до нажатия ролик не грузится — чтобы не съедать
трафик на мобильном). Урок отмечается пройденным по окончании ролика или
кнопкой «Отметить пройденным».

Итоговый тест — последним пунктом программы. Он открывается только после всех
обязательных уроков. Экран теста идёт без бокового меню: таймер, полоса
вопросов, «Далее», в конце — результат с процентом и порогом сдачи.

## 4. Метрики

- **Администрирование → Курсы** — сводка по всему обучению: назначено, в
  процессе, завершили, средний прогресс, процент сдачи тестов.
- **Уроки и тест** внутри курса — те же метрики по одному курсу.
- **Кабинет → Обучение** — личный прогресс сотрудника (теперь это реальная
  цифра, а не проставленная вручную).

## Обновление: загрузка больших видео и потеря введённых данных

### Видео до 500 МБ

Загрузка переведена на возобновляемую передачу кусками по 6 МБ. Раньше файл
уходил одним куском: на 500 МБ это десятки минут, и любой обрыв — уснувший
ноутбук, переключение с Wi-Fi на мобильный интернет — начинал всё заново.
Теперь загрузка продолжается с места обрыва, а в интерфейсе видно честный
процент и объём («120 МБ из 480 МБ»).

Отдельных действий с вашей стороны не требуется — только лимит тарифа выше.

### Данные больше не пропадают

Была ошибка в слое аутентификации. Возвращаясь на вкладку или открывая свёрнутое
окно, браузер заново проверяет сессию, и Supabase присылает событие входа для
того же самого пользователя. Портал считал это новым входом, показывал загрузчик
и **пересоздавал всё дерево страницы** — открытая форма и набранный текст
исчезали. Со стороны это выглядело как самопроизвольная перезагрузка.

Теперь профиль перечитывается, только если сменился пользователь.

Вдобавок длинные формы (урок, вопрос теста, новый пользователь) сохраняют
черновик в памяти вкладки: даже настоящая перезагрузка не заставит заполнять всё
заново. Пароль в черновик не пишется намеренно — он не должен оставаться в
хранилище браузера.
